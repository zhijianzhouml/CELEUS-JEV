04 / THE PROTOCOL

No hidden labels. No hidden full run.

01 / FREEZE

Define the evaluation pool

Pin dataset revisions, remove only predeclared oversize requests, and keep reference labels out of prompts.

02 / SAMPLE

Predict before querying

CELEUS learns from queried losses using CPU features and asks Jev one selected case at a time. Unselected cases are never evaluated. The EVALUE baseline uses a uniform random order.

03 / CERTIFY

Certify the fixed pool

CELEUS uses residual-corrected betting with outward numerical inversion. EVALUE retains exact hypergeometric PPR inference.

04 / COMPARE

Run full independently

Use a separate command, output directory and API ledger. Publish observed protocol differences.

Statistical scope, intervals and reproducibility

The default family error budget is 0.05, split over four benchmarks. The four 98.75% anytime-valid confidence sequences support at least 95% simultaneous coverage for the four fixed-pool means, under the stated sampling and fixed-outcome assumptions. When both methods are shown, the eight intervals do not have a joint 95% guarantee without another alpha split. The stopping rule is width ≤ 2ε; the midpoint then has error at most ε on the coverage event. This is not a claim about future deployment data, label correctness, Jev probability calibration, or cost/time uncertainty.

Assumptions: a frozen eligible pool, correct predictable sampling without replacement, and fixed per-case responses or a preassignable, order-independent random response mechanism. Mutable model versions or load/order-dependent drift are not covered. A fresh full API run need not realize the same random responses. Run many seeds only under a separately specified reporting and error-control protocol; do not select the best-looking interval.
